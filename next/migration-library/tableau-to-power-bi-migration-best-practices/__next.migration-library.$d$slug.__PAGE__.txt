<p>These are lessons from real migration projects — patterns that consistently work and pitfalls that consistently bite teams.</p>
<h2>Before you start</h2>
<p><strong>Run a proper assessment.</strong> Teams that skip the assessment phase consistently underestimate scope by 2–3x. A readiness score per workbook, not just a workbook count, is the minimum you need before giving stakeholders a timeline.</p>
<p><strong>Freeze your Tableau environment.</strong> Once migration starts, stop making changes to source workbooks. Changes mid-migration invalidate your conversion work.</p>
<p><strong>Establish a validation baseline.</strong> Export key metric values from Tableau before you start. You'll need these to verify Power BI output.</p>
<h2>During migration</h2>
<p><strong>Migrate dependencies first.</strong> If Dashboard B uses a calculation from Shared Data Source A, migrate A before B. Map your dependencies before you start.</p>
<p><strong>Don't convert everything — archive the stale content.</strong> Analysis typically shows 20–40% of workbooks haven't been accessed in 6+ months. Migrate what's used; archive the rest.</p>
<p><strong>Use a staging environment.</strong> Never convert directly to production. Validate in staging first.</p>
<p><strong>Document decisions.</strong> When you make a deliberate choice (e.g., "we're replacing this custom SQL with a simpler DAX approach"), document it. Your future self will thank you.</p>
<h2>Validation</h2>
<p><strong>Compare at the data level, not the visual level.</strong> Visual similarity doesn't mean the numbers are right. Export underlying data from both source and target and compare row counts, totals, and key metrics.</p>
<p><strong>Test edge cases</strong>: null values, date boundaries, top-N filtering, cross-filtering interactions.</p>
<p><strong>UAT with real users.</strong> No amount of technical validation replaces end users working with the reports they know.</p>
<h2>Cutover</h2>
<p><strong>Plan a parallel run period.</strong> Run Tableau and Power BI side-by-side for 2–4 weeks before cutting over. This catches calculation discrepancies before they become production issues.</p>
<p><strong>Have a rollback plan.</strong> Know exactly how you'd roll back to Tableau if something goes wrong post-cutover.</p>
